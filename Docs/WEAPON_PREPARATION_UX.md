# 층 선택과 무기 편성 UX

2026-10-07. 기존 게임 규칙과 `0df6213`까지의 기능을 유지한 UI 개편이다.

## 흐름

1. 층 카드에서 목표, 맵, 위험, 보상을 구분해 읽는다. 하단에는 왼손·오른손의 현재 무기를 아이콘과 이름으로 표시한다.
2. 현재 편성으로 바로 출발하거나 **무기 편성 열기**를 누른다. 편성은 필수 단계가 아니다.
3. 선택한 층의 맵·목표·난이도를 유지한 채 양손 편집 영역을 보여준다. 각 손의 세 슬롯은 실제 전투 휠과 같은 위·오른쪽 아래·왼쪽 아래 배치다. 시계 방향 텍스트를 해석할 필요가 없다.
4. 슬롯을 클릭하면 테두리와 **편집 중** 표시가 이동한다. 포커스 이동 자체는 무기를 바꾸지 않는다. 오른쪽 목록의 무기를 클릭해야 해당 슬롯만 바뀐다.
5. **편성 적용 · 돌아가기**로 변경을 한 번 적용한다. 적용 직후 연속 클릭이 출발로 이어지지 않도록 짧은 입력 보호를 둔다. **취소 · 돌아가기** 또는 Esc는 변경을 버리고 원래 편성과 선택한 층을 유지한다.

편성 중에는 **변경사항 미적용**, **현재 슬롯에 장착됨**, **같은 손의 다른 슬롯에 장착됨** 상태를 글자로 표시한다. 색만으로 상태를 구별하지 않는다. 슬롯 비우기는 별도 버튼이며 화면을 열자마자 빈 무기가 선택되어 있는 상태를 없앴다.

## 보존한 게임 규칙

- 양손 각각 세 슬롯. 인덱스 0/1/2는 전투 휠의 위/오른쪽 아래/왼쪽 아래와 동일하다.
- E는 왼손, Q는 오른손. 마우스 오른쪽 공격은 왼손, 마우스 왼쪽 공격은 오른손이다.
- 같은 손에 같은 무기를 중복 편성할 수 없다. 양손에 각각 편성하는 것은 가능하다. 빈 슬롯도 허용한다.
- 드래프트만 편집하고 확정 시 기존 RunManager API를 사용한다. 출발 시 기존 전투 편성 복사 경로를 그대로 사용한다.
- 층 후보 생성, 목표 중복 규칙, 난이도, 보상, 경로 확정 규칙은 수정하지 않았다. 목표 두 개가 같은 경우는 허용하고 세 개 모두 같은 경우만 금지한다.

## 임시 아이콘과 역할

`WeaponPlaceholderIcons.Generate`가 Unity Texture2D로 PNG와 Sprite import 설정을 만들고 SerializedObject API로 각 WeaponDefinition.Icon에 연결한다. 외부 이미지나 유료 에셋을 쓰지 않았다. 같은 Icon 참조를 쓰는 편성창과 전투 Q/E 휠에 모두 반영된다. 기존 아트와 아이콘은 삭제하지 않았다.

| 무기 | 단색 실루엣 | 코드에서 확인한 역할 |
|---|---|---|
| Shooter | 짧은 노즐과 한 발 | 누르고 기본 연사 |
| Splash Bomb | 둥근 폭탄과 튀는 방울 | 충전 시간으로 투척 거리 조절, 범위 폭발 |
| Machine Gun | 드럼과 여러 탄환 | 지속 사격으로 연사 속도 증가 |
| Breach | 갈라진 판을 통과하는 화살표 | 관통 투척 후 재입력으로 돌진 |
| Blade | 대각선 칼날과 손잡이 | 클릭마다 근접 휩쓸기 |

## 검증 방식

`WeaponPreparationValidation.Start`는 실제 InputSystem 마우스·키 이벤트와 EventSystem raycast를 사용한다. 층 클리어와 첫 보상은 테스트 준비를 위해 통제하고, 편성 UI의 열기·포커스·배치·비우기·취소·적용·출발과 전투 Q/E 휠은 입력으로 확인한다.

1280×720, 1024×768, 2560×1080에서 GPU 캡처, TMP 텍스트 잘림, 버튼 화면 경계와 버튼 간 겹침을 검사한다. 보유 무기 전부의 Sprite 참조와 픽셀 데이터가 다른지도 확인한다. 확정한 배열이 전투 슬롯·휠 아이콘·키를 놓을 때 선택되는 슬롯과 일치해야 통과한다.

결과 로그·빌드 식별자는 작업 루트 `LATEST_DELIVERY.md`와 `LATEST_DELIVERY_IDENTITY.json`에 기록한다. 상세 수치 밸런스, 전체 런 자연 플레이, 임의 해상도와 모든 입력 장치 검증은 이번 범위에 포함하지 않는다.

최종 편성 검증은 `weapon-preparation-validation-final.log`에서 **1,200개 검사 통과**, 종료 코드 0을 기록했다. 이 수에는 세 해상도에서 반복한 텍스트·버튼 배치 검사가 포함된다. 첫 실행은 이미 활성화된 전투 슬롯을 다시 선택하려는 테스트 조건 때문에 실패했으며, 현재 슬롯 이외의 슬롯을 선택하도록 테스트만 수정한 후 통과했다. 기존 휠의 활성 슬롯 재선택 제외 규칙은 변경하지 않았다. 알려진 UnityEditor.Search.SearchDatabase 초기화 예외는 에디터 환경 문제로 제외했고 게임 오류 검사는 통과했다.

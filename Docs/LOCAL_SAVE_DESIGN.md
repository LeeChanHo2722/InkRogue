# 로컬 저장, 이어하기, 런 기록

현재 게임의 층 진행 순서를 유지하며 활성 런 1개와 종료 기록을 저장한다. 계정·온라인 저장·다중 슬롯·전투 전체 스냅샷은 포함하지 않는다.

## 플레이 규칙

- 메인 메뉴의 **이어하기**에서 모드, 층, 목숨, 저장 시각, 복원 단계를 확인한다.
- 전투 중 Esc → **저장하고 메뉴로**. 전투가 끝난 안전 구간에도 같은 버튼이 있다.
- 전투 중 종료/강제 종료에는 추가 목숨 차감이 없다. 마지막 층 진입으로 돌아가며 그 층의 적, 위치, 잉크, 전투 진행은 초기화한다. 정상 사망으로 차감한 목숨은 유지한다.
- UI 안내: “이번 층의 전투 진행은 저장되지 않습니다. 이어하기는 이 층 시작 시점으로 돌아갑니다.”
- 파워·경로 선택 중에는 그 단계로 돌아간다. 생성된 후보를 저장하므로 다시 실행해도 재추첨하지 않는다.
- 확정한 좌우 3칸 편성은 유지한다. 편성 창에서 적용하지 않은 초안과 단순 카드 강조 표시는 버린다.
- 새 런을 시작할 때 기존 활성 런이 있으면 확인한다. 취소하면 파일을 바꾸지 않는다. 확인하면 이전 런은 **중단** 기록이 되고 새 런으로 교체한다.
- 지난 런 기록은 최신순 5개씩 표시한다. 상세에서 모드, 결과, 날짜, 도달/클리어 층, 보스 처치, 정상 사망, 목숨, 시간, 최종 능력과 장비를 확인한다.
- 캠페인은 20층 최종 보스로 승리한다. 무한 모드에는 승리 종료를 추가하지 않았다.

## 확정 경계

| 단계/이벤트 | 같은 저장 트랜잭션의 내용 | 재개 동작 |
|---|---|---|
| 신규 런 및 층 진입 | 모드·시드·층 구성·확정 편성·파워·체력·목숨 | 해당 층 시작 |
| 정상 사망 / 방어 목표 파괴 | 정상 사망 횟수·남은 목숨·시간, 기존 층 시작 체크포인트 | 층 시작 + 이미 차감한 목숨 유지 |
| 보스 확정 처치 → 일반 보상 | 기존 `RecordBossDefeated`의 중복 방지 값·보스 수·목숨 +1(cap 3)·층 보상·파워 후보 | 파워 선택 |
| 일반 층 클리어 | 자동 보상 처리 값·보상 수·생성된 파워 후보 | 파워 선택 |
| 수동 파워 확정 | 선택 능력 증가(또는 만렙 정비 소비)·생성된 경로 후보 | 경로 선택 |
| 장비 적용 | 완성된 좌우 편성 전체 | 경로 선택; 미확정 초안 제외 |
| 경로 출발 확정 | 선택 후보·고정 encounter seed·이동 단계 | 확정 경로 이동을 재실행; 성공 시 한 번 층 증가 |
| 승리/패배 | 활성 런 제거 + runId별 종료 기록 | 메뉴/기록; 종료 런 이어하기 불가 |
| 새 런 교체 확인 | 이전 런 중단 기록 + 새 활성 런 | 새 런 시작 |

사망은 연출 전에 확정 저장한다. 방어 구간의 플레이어 사망은 기존 규칙대로 목숨을 차감하지 않으며 사망 횟수만 기록한다. 방어 목표 파괴는 기존 목숨 비용을 저장한다. 0목숨의 종료 런은 보스 보상으로 부활하지 않는다.

보스 사망 연출 도중의 전투 종료는 아직 기존 `RecordBossDefeated` 확정 경계에 도달하지 않은 경우다. 해당 층 시작 체크포인트로 재개한다. 전투를 스냅샷하지 않는 동일한 규칙이다.

## 저장 데이터와 복원

스키마 1은 runId, revision, 생성/저장 시각, 모드/층/단계/런 시드, 시작 맵, 체크포인트 방어막, 목숨/사망, 시간/누적 피해, 보스/보상 수와 마지막 처리 층, 인벤토리와 좌우 슬롯의 안정적인 WeaponId, 플레이어/로봇의 모든 파워 단계, 파워 후보, 선택 경로, 경로 후보, 최근 두 경로, 준비한 층 번호, 첫 층 encounter seed를 보존한다.

FloorDefinition은 FloorId로 다시 연결한다. 맵·무기가 현재 빌드에 없으면 재개 오류를 표시하고 파일을 보존한다. 파워로부터 로봇의 기본 공격력·주기·효과를 다시 구성한다. 적, 탄환, 잉크 맵, 전투 중 위치/쿨다운, 현재 무기 휠 강조는 저장하지 않는다. 신규 층/부활의 기존 초기화 규칙을 사용한다.

## 파일 무결성

- 기본 위치: `Application.persistentDataPath/RunSaves`.
- `runs.json`: 버전·SHA-256이 포함된 활성 런 + 기록 묶음.
- 같은 디렉터리 임시 파일에 전체 내용을 쓰고 디스크 flush 후 `File.Replace`/최초 `File.Move`로 커밋한다.
- `.bak`은 이전 유효 저장이다. 손상 주파일에서 복구한 뒤 저장할 때 손상본을 정상 백업 위에 복사하지 않는다.
- 떠도는 `.tmp` 파일은 복구 입력으로 사용하지 않는다.
- `ended-<runId>.json`은 종료/중단 영수증이다. 이전 백업이 종료 런을 되살리지 않도록 확인한다. 교체 트랜잭션에는 새 활성 체크포인트도 포함한다. 영수증 직후 중단되어도 활성/종료 상태의 완전한 조합을 복구한다.
- 필수 필드 누락, 잘린 JSON, 불가능한 값, 지원 불가 버전은 조용히 초기화하지 않는다. 유효 백업 복구는 안내한다. 복구 불가 파일의 교체는 새 런 확인 후 원본을 `preserved-*` 하위 폴더에 복사 보존하고 수행한다.
- 쓰기 실패는 진행을 멈추고 **다시 저장**을 표시한다. 동일한 준비 트랜잭션을 재시도하므로 보상/사망을 다시 적용하지 않는다. 저장 성공 전 메뉴 복귀를 성공 처리하지 않는다.
- Unity 기본 JsonUtility는 null 클래스를 빈 객체로 바꾸므로 사용하지 않는다. 프로젝트에 이미 포함된 Newtonsoft JSON을 사용하고 파일의 런타임 타입 메타데이터는 허용하지 않는다.

## 검증 재실행

실제 사용자 저장을 테스트에 사용하지 않는다. 프로세스 실행 전에 `INKROGUE_SAVE_TEST_PATH`를 별도 절대 경로로 지정한다.

- Unity Editor `RunSaveValidation.Pure`: 임시/교체 실패, 백업, 손상, 필수 필드, 버전, 값 범위, 종료/교체 원자성.
- `TowerPlayValidation.Start`: 실제 캠페인 승리, 무한 20→21, 정상 사망, 보스 회복과 중복 호출, 패배.
- 실행 파일에 `-inkrogue-save-probe write-combat|write-power|write-route|write-travel` 후 별도 PID에서 `read` 또는 `read-ui`. 격리 경로 환경변수와 명시 인수가 모두 있어야 진단 코드가 동작한다. 일반 실행에서는 비활성이다.
- 작업 루트의 `run-save-process-tests.ps1`은 직접 시작한 전투 writer PID만 강제 종료하고 새 reader 프로세스를 띄운다. 결과 JSON에 두 PID를 남긴다.

검증 결과와 정확한 빌드 식별자는 작업 루트의 최종 체크포인트에 기록한다. 실제 전원 차단/디스크 하드웨어 오류는 재현하지 않으며 파일 경계 실패 주입과 실제 프로세스 강제 종료로 검증한다.

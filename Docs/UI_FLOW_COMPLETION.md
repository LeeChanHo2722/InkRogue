# 핵심 UI 흐름 정리

2026-10-07. `900f390` 이후의 UI 수정 단위. 기존 임시 그래픽과 계층을 유지했다.

## 수정

- 보스 HUD가 표시되는 동안 공통 런 상태를 화면 하단으로 옮겨 보스 이름·페이즈와 분리했다. 일반 전투에서는 상단에 둔다.
- 보스 체력바와 목숨 HUD의 실제 영역을 비교해 좁은 화면에서는 체력바를 옆으로 옮긴다. 가로 공간이 부족하면 아래 행을 사용한다. 기존 Constant Pixel Size Canvas 설정은 유지했다.
- 보스 등장 제목에 대응 문구가 포함돼도 넘치지 않도록 제목 영역을 확보하고 WARNING과 분리했다.
- 런 메뉴·파워·일시정지·결과 화면의 기존 Scale With Screen Size Canvas에 Expand를 적용해 4:3과 울트라와이드에서 버튼/설명이 잘리지 않게 했다.
- 테스트용 카메라 캡처는 overlay Canvas의 정렬을 보존하며, 캡처 뒤 기존 설정을 복구한다.

## 기능 검증

`TowerUIFlowValidation.Start`는 InputSystem 가상 마우스/키보드의 실제 이벤트를 EventSystem에 전달한다. 버튼 핸들러를 직접 호출하는 것으로 입력 검증을 대신하지 않는다.

메뉴의 두 모드 선택, Esc 일시정지, 마우스 재개, 파워 수동 선택, 층 카드 미리보기와 출발, 보스 등장, 승리·패배 결과와 재시작을 확인한다. 층 클리어·보스 피해·목숨 소진은 빠른 진행을 위한 제어 fixture다.

1280×720, 1024×768, 2560×1080에서 GPU 렌더와 버튼 영역, 텍스트 넘침, 보스 HUD 겹침을 확인한다. 네 보스의 1·2·3페이즈를 각각 확인하고 실제 체력 임계치 전환에서 무적, 이전 경고 취소, 새 패턴과 예고 재개를 검사한다. 상세 수치나 장시간 전투 검사는 아니다.

## 승인 요구사항 상태

| 요구사항 | 상태 |
|---|---|
| 사격 → 영역 변화 → 잠수·잉크 충전, 양손 장비 | 기존 구현 유지. 이전 입력·파워 회귀 통과 |
| 층 선택에서 같은 목표 2개 허용, 3개 동일만 금지 | 구현 및 기존 후보 검증 완료 |
| 맵·목표·난이도 표시, 미리보기 후 확정, 무기 준비 적용/취소 | 구현. 실제 UI 입력 및 이전 draft 검사 완료 |
| 난이도별 최대 2/3/4 파워 후보 중 1개 수동 획득 | 구현. 실제 선택, 중복 보상 차단, 최대 단계 제외 검사 완료 |
| 런 공통 목숨, 보스 +1, 최대 3 | 구현. 사망·층 이동·보스·재시작 회귀 완료 |
| 총 파워 단계 자동 기본 화력 증가 제거 | 구현. 노즐·모터 직접 선택만 기본 화력 성장 |
| 플레이어·로봇 파워 다양화와 소유자 분리 | 20종 구현. 효과·재귀·쿨다운·선택 검사 완료 |
| 개성 있는 보스 4종 | 이동·공격·대응 차이 구현. 모든 체력 페이즈 기능 smoke 완료 |
| 20층 승리, 무한 계속 진행, 패배·재시작 | 구현. 관련 경계 검사와 이번 실제 결과 버튼 입력 완료 |
| 보스 HUD 및 핵심 화면 겹침 | 이번 단위에서 수정·렌더 확인 |
| 일반 층 약 90초, 동일 투자 플레이어100:로봇60 | 수치 목표이며 본격 QA로 보류. 달성했다고 표시하지 않음 |
| 정식 그래픽·음원 제작, Steam 배포 | 이번 승인 범위 밖. 제작/게시하지 않음 |
| 런 저장·이어하기 | 확정 요구사항이 아닌 선택사항. 이번에 추가하지 않음 |

현재 검사한 흐름에서 재현 중인 진행 불가·보상 중복·UI 겹침은 없다. 전체 런 자연 플레이, 임의 해상도 및 모든 입력 장치 조합, 장시간 전투와 상세 밸런스는 검증 범위 밖이다. 최신 실행 파일·로그·커밋 식별자는 작업 루트의 LATEST_DELIVERY 문서에 기록한다.
